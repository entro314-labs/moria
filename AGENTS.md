# Moria

Native macOS deep file search: filenames, contents, regex, meaning. SwiftPM package, no Xcode project.

## Layout

- `Sources/MoriaCore` — engine, shared by the app and CLI.
  - `Crawl/` — `Crawler` (fts(3) walk, exclusion and content-scope rules), `PipelinedCrawl` (crawl thread with backpressure).
  - `Database/` — `IndexDatabase` (schema, settings in `meta`), `FileStore` (`MetadataWriter`, extraction/embedding storage), `Folding` (diacritic-folding FTS5 tokenizer `moria_fold`).
  - `Extract/` — `ContentExtractor` (text/PDF/Office/zip/HTML/OCR), `Transcriber` (SpeechAnalyzer for audio/video), `MaterializationGuard` (blocks cloud downloads), `ProcessRunner`, `AsyncLimiter`.
  - `Index/IndexController` — the one actor that scans, applies FSEvents changes, extracts and embeds.
  - `Search/` — `QueryParser`/`SearchQuery`, `QueryFormatter`, `SearchEngine` (RRF fusion, on-demand snippets, `similar:`), `RegexSearcher` (ripgrep + stored text), `NaturalLanguageQuery` (Foundation Models), `Stemmer` (Greek/Russian query stems).
  - `MCP/MCPServer` — `moria mcp`: JSON-RPC tools over the index, transport-free so it is testable. Dual-era: the `initialize` handshake (revisions to 2025-11-25) and per-request `_meta` versions with `server/discover` (2026-07-28).
  - `Semantic/` — `Embedder` (NLContextualEmbedding, mean-pooled), `VectorIndex` (in-memory Float16, vDSP), `Answerer` (retrieve passages, then Foundation Models writes an answer citing them).
  - `Watch/FileWatcher` — FSEvents stream.
- `Sources/CSnowball` — vendored Snowball runtime with the UTF-8 Greek and Russian stemmers (BSD).
- `Sources/MoriaCLI` — the `moria` executable (target `moria`).
- `Sources/MoriaApp` — the app (target `MoriaApp`, bundled as `Moria.app`). Default isolation is `MainActor`.
- `Scripts/release.sh <version>` — a release: bumps `version.env` (build number +1) and dates the changelog, runs the tests, builds with the Developer ID identity (secure timestamps), notarizes and staples the app and `build/Moria-<version>.dmg`, adds it to the Sparkle feed (`appcast.xml`, fetched from the latest release, signed with the update key, notes from the changelog), then commits, tags, pushes and publishes the GitHub release. `DRY_RUN=1` builds the disk image and feed only and puts the version files back. Notarization credentials: keychain profile `moria` (`NOTARY_PROFILE`).
- `Scripts/release.env` — the GitHub repository, the update key's public half and keychain account, and the pinned Sparkle tools version.
- `Scripts/package_app.sh` — builds and signs `build/Moria.app` with bundled ripgrep and icon, and generates the App Intents metadata (`Metadata.appintents`) that Xcode would: SwiftPM compiles the constant values but doesn't run `appintentsmetadataprocessor`, so the script does. Without it the Shortcuts actions (`App/Intents.swift`) don't exist to the system.

## Key design decisions

- Schema: folders keep full paths in `dir`; files store `(dirId, name)`. Both FTS5 tables are contentless; only PDF/Office/OCR text is stored (`doc_text`). Snippets are built on demand (`SearchEngine.snippet`).
- Content scope: names are indexed everywhere; text is extracted only outside `~/Library`, hidden folders and dependency/build folders (`contentState = 5` = excluded). Symlinks are names only (`7`); their targets are read where they live.
- Changing an extraction setting marks indexed files stale (`contentState = 6`): their text stays searchable until they are read again. The invalidation trigger treats 1 and 6 alike.
- Settings live in the index (`meta`); the running app re-reads them (`IndexController.reloadSettings`) so `moria config` changes apply. A change to what is crawled clears the FSEvents resume point until a full scan completes.
- Stemming: the content index stems English at index time (FTS5 `porter`). Greek and Cyrillic (Russian) words are stemmed at query time with vendored Snowball (`Sources/CSnowball`, `Stemmer`) and searched as a prefix of the stem, which the stored folded forms share, so no re-indexing is involved. Latin-script words in other languages aren't stemmed: their language can't be told from the word.
- Regex: names and stored text use ICU; files use ripgrep with `--engine auto` (PCRE2 when a pattern needs it). Case-sensitive patterns carry `(?-i)`. Homebrew's ripgrep, linked against Homebrew's PCRE2, misses some PCRE2 matches; the app bundles the official static build.
- Updates: Sparkle (`Support/Updates.swift`) reads `SUFeedURL`, `https://github.com/<repo>/releases/latest/download/appcast.xml`, so the newest release's feed is the feed. Updates must be EdDSA-signed with the keychain key (`SUPublicEDKey`) and code-signed like the running app. Without `SUFeedURL` (unbundled runs, tests) updates are off. `package_app.sh` embeds `Sparkle.framework`, adds `@executable_path/../Frameworks` to the rpath and signs Sparkle's helpers innermost first.
- The process sets `IOPOL_MATERIALIZE_DATALESS_FILES_OFF` so reading a cloud placeholder fails instead of downloading it. Keep it that way.
- External drives: `fsevents.volumes` (meta) records each location's mount point and FSEvents database at its last scan. A location whose recorded volume isn't mounted is offline: full scans don't crawl or prune it, `apply` ignores its changes (an eject reports everything as gone), extraction and embedding skip it, and results under it are `isOffline`. Connected locations on other volumes are crawled again at launch and when FSEvents reports their root changed.
- Finder tags are a `file.tags` column ("\nRed\nWork\n", NULL when untagged), read during the crawl only where contents are read: `getxattr` costs ~25 µs per file even when absent. The upsert always takes the tags read, since tagging changes neither mtime nor size.
- Transcription (`transcribeRecordings`, off by default): audio and video are crawled as pending only while it is on (`MetadataWriter.initialState`); toggling it requeues both kinds, so turning it off drops transcripts at the next read. `Transcriber` runs Apple's `SpeechAnalyzer` in the system language (English when it has no model), installs the language's assets on first use, and skips recordings over three hours. Transcripts are stored in `doc_text` like PDF text (`keepsExtractedText`), one `[m:ss] words` line per phrase, so snippets carry times and `Transcriber.time(of:)` turns a match line into a seek. Extraction has three phases (`ExtractionPhase`: text, images, recordings) so OCR and transcription never hold up text; recordings run one at a time. A missing or undownloadable speech model is reported as `IndexProgress.transcriptionProblem` and retried every 10 minutes, with the recordings left pending.
- Media details (`taken`, `duration`, `author`) are read by a separate pass (`MediaReader`, `file.mediaState`: 0 pending, 1 read, 2 not applicable) for photos, audio, video, PDFs and documents where contents are read. `v5-media` adds the columns with the constant default 2 so the migration never rewrites rows; `backfillMediaIfNeeded` queues existing files once (`media.backfilled`). A trigger clears the details when a file leaves state 1, as content is cleared.
- Photo labels come from Vision's `ClassifyImageRequest` in the details pass, kept only at ≥90% precision (lower cuts invent labels on screenshots), and only for images worth recognizing (as for OCR). They live in `file.labels` and a separate contentless `label_fts`, fused into search as a fourth list (`matchedLabel`), and are cleared with the other details (`v6-labels` recreates `file_ad` and the details trigger).
- Duplicates (`duplicates:yes`, `Search/Duplicates.swift`): same-size candidates from SQL, then a hash of the first 64 KB, then a full hash only where heads match; hashes are cached in `file_hash` (`v7-hashes`) while size and mtime match. Hard links count once; cloud-only files are never read.
- Schema changes go in new migrations (`v3`, …): real indexes exist with `v1` and `v2-filter-indexes` applied; `v3-stale-content`, `v4-tags`, `v5-media`, `v6-labels` and `v7-hashes` are applied the first time a build with them opens an index (`v4-tags` drops the resume point so the next start scans for tags). Never edit applied migrations.
- Answers (`Answerer`, Answer mode, `moria search --answer`): retrieval is the ordinary search with only the words the model picks out of the question (`NaturalLanguageQuery`; its kinds and dates are guesses that hide the answer), falling back to the question's distinctive words and then to its longest words; each candidate's best passage (the densest window of term hits, or Meaning's chunk) goes to a fresh `LanguageModelSession` whose instructions forbid answering outside the sources, streamed as the whole text so far. The on-device context window is small: at most 6 sources of 600 characters, halved on `exceededContextWindowSize`. Citations `[n]` map to the sources in order, which are also the result rows. Gated on the Ask setting (same model); not offered over MCP, since agents bring their own model (`docs/rejected-ideas.md`).
- `MoriaSettings` decodes missing keys with defaults; keep that when adding settings.

## Build, test, run

- `swift build`, `swift test` (Swift Testing; tests use temp directories only). `MoriaCoreTests` covers the engine; `MoriaAppTests` covers app logic with an `AppModel` on a scratch index and its own defaults (`makeAppModel()`).
- `swift build --product MoriaApp && .build/debug/MoriaApp -initialQuery "invoice" -indexPath /tmp/x.sqlite` runs the app unbundled (no Full Disk Access of its own) on a scratch index.
- `Scripts/package_app.sh` then `open build/Moria.app` for the real thing. It signs with the first "Apple Development" identity so Full Disk Access survives rebuilds.
- `.build/debug/moria --help` for the CLI; `--db <path>` points it at a scratch index.
