# Project review, 2026-09-29: fidelity, currency, opportunity

Three passes over the whole codebase (13,200 lines of Swift, every file read), the tests
(63 core + 9 app at the start, all passing), the docs and the release scripts. Findings are
numbered F- (fidelity), C- (currency) and O- (opportunity); the register in section G orders
them. Fixes made during the review are on the branch `audit/fidelity-fixes`, one commit each,
not pushed.

## A. Reconstructed intended logic

Sources, strongest first: `AGENTS.md` "Key design decisions", the schema and migrations
(`IndexDatabase`), the tests, then UI copy and comments.

**Actors.** One local user, through four surfaces that share one index file: the app
(`MoriaApp`), the `moria` CLI, `moria mcp` (AI agents), and Shortcuts (`FindFilesIntent`,
`OpenSearchIntent`). No accounts, no tenants, no network: "Everything is indexed on this Mac and
never leaves it" (About panel, Help). Permissions are the OS's: TCC (Full Disk Access) and the
process-wide `IOPOL_MATERIALIZE_DATALESS_FILES_OFF`, which must never be removed (explicit).

**Entities.** `dir` (full path, scan generation), `file` (`dirId`, `name`, stat data, `kind`,
flags, `contentState`, `embedState`, `mediaState`, `tags`, details, `labels`), contentless FTS5
tables `name_fts`, `content_fts` (`porter moria_fold`), `label_fts`; `doc_text` only for
PDF/Office/OCR; `chunk_vec` (Float16); `file_hash`; `meta` (settings JSON, resume point,
volume records, backfill markers, `embeddings.version`).

**Lifecycles (explicit, from `ContentState`/`MediaState` and the upsert in `MetadataWriter`).**
- `contentState`: 0 pending → 1 indexed | 2 none | 3 failed; 4 cloud-only, 5 excluded, 7 link are
  set by the crawl from the file's flags and location; 6 stale is only reachable from 1 through
  `requeueContent`, and 6 keeps its text until re-read. Any move out of {1, 6} drops text,
  stored text and vectors (trigger `file_content_invalidated`). A change of mtime/size/cloud
  flag resets to the crawl's initial state. Moving across the content-scope boundary flips 5.
- `mediaState`: 0 → 1; 2 not applicable; leaving 1 clears the details and labels (trigger).
- `embedState`: 0 waiting, 1 embedded, 2 never (code, Library, hidden; set at store time and
  by a one-off `markNotEmbeddable`).
- Extraction results are dropped if mtime changed since listing (`store` checks mtime and
  state ∈ {0, 6}); a file that changes three times while waiting is marked 3 until its next
  change (explicit, commit 7a3bd9e).

**Invariants.** Illegal states are prevented by the upsert CASE and the triggers, not by CHECK
constraints; the rebuild test asserts no orphan files. Deleting a subtree deletes by path range
on `dir.path`. Prune after a full scan spares locations whose volume is offline (explicit,
"External drives"). Settings changes that alter what is crawled clear the FSEvents resume
point before anything else can resume (explicit). Migrations are append-only (explicit).

**Search semantics.** Words match names (trigram, short words as prefix) or contents (prefix
of the folded stem); RRF fusion with fixed weights; `-word` applies in SQL so it also works
without words and on meaning matches; typed filters win over sidebar filters (UI copy:
"a filter you type wins"); Names/Contents modes move words, never `name:`/`content:`
tokens. Inferred, high confidence: `content:x word` searches `word` in contents only
(`nameMatches` bails when `contentTerms` is non-empty) — documented nowhere but consistent
with "only contents" (see H).

**Side effects and time.** Extraction, details and embedding run in one actor loop; the UI
gets throttled progress. Move to Trash updates the index directly because FSEvents ignores the
process's own changes (explicit). Dates use the user's calendar; EXIF times use their recorded
offset or local time (explicit, tested). Meaning vectors reload at most once a minute
(explicit).

**Unclear rules** are listed in H.

## D. Cross-flow consistency gaps

- **Drop vs Choose vs root (accidental):** three ways to pick a folder, one canonicalized. Fixed (F-05).
- **App vs CLI settings (accidental):** fixed (F-01). The app's Contents pane still has no minimum below 32 KB while the CLI accepts any positive number and the extractor clamps at 4 KB; harmless, documented in a test.
- **Regex filters (accidental):** app and MCP narrow regex searches with filters; the CLI cannot (O-01).
- **Edit… on saved searches (accidental, harmless):** a regex saved search is applied to the window before its builder opens; a criteria search is not. Both builders load from `editing.text`, so the apply is redundant. Left.
- **Unknown tool (intentional):** result with `isError`, differs from the spec (F-07).
- **Counting (accidental):** sidebar and Home count collections by running the search with limit 1000; the criteria builder now counts the same way Search runs (F-03).

Classification:

- **C-01 MCP 2026-07-28 — upgrade with migration, done.** The current revision removes
  `initialize`/`notifications/initialized` and `ping`, carries the version in every request's
  `_meta`, requires `server/discover` ("Servers MUST implement it"), `resultType` on every
  result, `ttlMs`/`cacheScope` on `tools/list`, and `UnsupportedProtocolVersionError` (-32022)
  for unknown versions. Per the compatibility matrix a modern client fails against a
  legacy-only stdio server; a dual-era client probes `server/discover` and falls back. Moria is
  now dual-era (`MCPServer.swift`, test `perRequestVersionsAreServedWithoutAHandshake`):
  handshake responses carry the same fields and values as before (the test asserts them; key order was never stable). Left out on purpose: `subscriptions/listen`
  (tools never change), MRTR, `structuredContent`.
- **C-02 Snowball 3.0.1 → 3.1.1 — hold intentionally.** NEWS for 3.1.0/3.1.1 lists no change to
  the Greek or Russian algorithms; the C changes are runtime refactors (`runtime/header.h`
  renamed to `snowball_runtime.h`, among functions by index, `-vprefix` getters). Re-vendoring
  means regenerating both stemmers with the 3.1.1 compiler for no change in results.
- **C-03 Sparkle 2.10.0 — current; note.** All six advisories (GHSA-hg88…, -g3hp…, -gmj2…,
  -3x7w…, -4v99…, -wc9m…) are fixed at or before 2.9.6. Two `generate_appcast` fixes are merged
  on `2.x` but unreleased (#2925 locale recording, #2927 stale `sparkle:format` with embedded
  HTML notes); `release.sh` embeds Markdown notes, so #2927 does not apply. Any bump must change
  `Package.swift`, `SPARKLE_VERSION` and `SPARKLE_SHA256` together (`release.env` says so).
- **C-04 swift-subprocess 1.0.0 — current; `.data(limit:)` not applicable.** It throws
  `outputLimitExceeded`; `ProcessRunner.output` wants the first N bytes and a stopped child
  (unzip of a huge `sharedStrings.xml`), so the manual truncation stays.
- **C-05 GRDB 7.11.1 — current.** 7.9.0's "Fix cancellation of async tasks that use the FTS5
  full-text engine" is the fix Stop Search (commit 7c77553) relies on; already included.
- **C-06 SwiftUI flow layout — not applicable.** The macOS 26 SDK's SwiftUI interface declares
  `GridLayout` and `AligningContentProviderLayout` only; `FlowLayout` (HomeView) stays.
- **C-07 Toolchain — current, with a note.** Swift 6.4 / tools-version 6.4 are current. The
  machine runs a superseded Xcode 27.2 beta; `package_app.sh` stamps
  `appintentsmetadataprocessor` with `xcodebuild -version`, so releases should be built with the
  released Xcode 27 (or the current beta), not this one.
- **C-08 Lint/format — none configured.** No `.swiftformat`, `.swift-format` or `.swiftlint.yml`.
  Validation here was the compiler (no warnings in changed files) and the tests. Adding a
  formatter is a tooling decision for the owner; not proposed as a finding.
- Cosmetic bumps: none available.

## H. Specification gaps

- `content:lease invoice`: is `invoice` meant to match names too? The code searches it in
  contents only (`nameMatches` returns nothing when `contentTerms` is set). Consistent with
  "only contents" but undocumented; the criteria builder's "Contents contains" + "Name or
  Contents contains" rows produce exactly this. Left as is; document if intended.
- `NSOpenPanel` and symlinked folders: not verified whether it returns the link or the target.
  The canonicalization now applied to every chooser is correct either way.
- MCP "unknown tool": result vs protocol error (F-07). The comment states the intent; the spec
  says protocol error. Owner's call.
- Duplicates on offline volumes: `sameSizeFiles` includes offline files; `inode()` fails for
  them and they are skipped silently. Intended? They can't be hashed, so the outcome is right,
  but a group that spans an ejected drive is reported without those copies.
- Meaning results within a minute of a content change may use the old vectors (documented
  60-second reload). Acceptable by design; noted because F-02 shows the same cache can be wrong
  in a worse way after a rebuild.
